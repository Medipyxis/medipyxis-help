How are dates checked before a patient import?

whats-new Import Updated 2026-11-26

When you review a patient file before importing, dates written as MM/DD/YYYY are read month-first and shown converted (12/31/1955 becomes 1955-12-31, 04/05/1950 becomes 1950-04-05), and the review screen no longer says the file has mixed formats.

What changed when reviewing import dates?

No sound · 1 minute 2 seconds (half speed) · a text description of the video is below

When you review a patient file before importing, dates written as MM/DD/YYYY are read month-first and shown converted (12/31/1955 becomes 1955-12-31, 04/05/1950 becomes 1950-04-05), and the review screen no longer says the file has mixed formats.

Why it matters: A file that uses one date format all the way through passes the date check, and only dates that could read either way, like 04/05/1950, are flagged for you to confirm.

Text description of this video

The video has no sound and plays at half speed (1 minute 2 seconds).

A clinician is in Practice Onboarding, on the Patients import step. They upload a patient file and map the columns, including Date of Birth.

On the review screen, a “Check dates before importing” banner says Date of Birth values written as MM/DD/YYYY were read month-first and converted to YYYY-MM-DD, with examples 12/31/1955 → 1955-12-31 and 04/05/1950 → 1950-04-05. The file is not treated as mixed-format. A warning says some dates were ambiguous and assumed US month-first, and to verify Date of Birth on row 3. The listed rows are Ready. Import is not started.
